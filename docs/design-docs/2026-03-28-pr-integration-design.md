## Problem Statement

Three connected problems in claude-remote-cli's PR and branch management:

1. **Branch picker broken** — The branch picker in the running app renders as a text input that doesn't open a dropdown. BranchSwitcher.svelte looks functional in code (has open/close state, filtering, async branch loading), and SearchableSelect.svelte exists but nothing imports it. Root cause needs runtime investigation, likely a CSS/event issue rather than a logic bug.

2. **Missing "Review PR" CTA in dashboard** — When a PR has `role: 'reviewer'` and `reviewDecision: 'REVIEW_REQUIRED'`, the RepoDashboard table shows only "Merge" and "+" buttons. The `prActionForRow()` function in RepoDashboard.svelte hardcodes `unresolvedCommentCount: 0` and doesn't pass the user's role to `derivePrAction()`. The pr-state.ts state machine derives actions from PR state alone, ignoring whether the current user is the author or a reviewer. This means a reviewer on a mergeable PR sees "Merge" as the primary action, when they should see "Review."

3. **Unified picker not implemented** — The open-from-picker design doc (`2026-03-27-open-from-picker-design.md`) describes a Cursor-style unified picker modal for branches, PRs, and issues. Designed but unbuilt. The existing Spotlight.svelte component provides the modal infrastructure.

## What Makes This Cool

The picker isn't a dropdown. It's a command palette for your dev workflow.

You're on the bus with 5 PRs open. You tap the picker, see "needs your review" at the top with a blue "review" button. One tap starts a Claude session that reads the diff, runs tests, and produces a code review, all while you're commuting. When you get to work, you open the same picker, switch to the issues tab, tap "start" on a bug, and it auto-creates a branch, worktree, and session with the issue context preloaded.

The magic is in the "intent, not object" model. Each picker result doesn't just show the item. It shows what YOU should do with it based on your role and the item's state. A reviewer sees "review." An author with conflicts sees "fix conflicts." A branch with an existing session shows "resume." The picker resolves to actions, not just navigation.

Every AI code review tool on the market (CodeRabbit, Greptile, Graphite) is a comment bot: PR opens, bot posts comments. claude-remote-cli is different. "Review" starts an interactive Claude session in a PTY. The session is the product. The picker is just the door.

## Constraints

- Must work on mobile (touch targets >= 44px, full-screen picker on small screens)
- Must follow DESIGN.md: pure black bg, monospace only, 0 border-radius, outline-only buttons, fzf `>` cursor
- Must build on existing Spotlight.svelte modal infrastructure
- GitHub GraphQL API is already shipping (Phase 2 complete) — rich PR data available
- No new backend dependencies; use existing session manager, worktree creation, and branch APIs
- npm package distribution is already in place

## Premises

1. The branch picker bug is real (confirmed in running app) and needs investigation/fix
2. The PR dashboard should surface role-aware action buttons inline, not just in the session top bar
3. The open-from-picker modal is the highest-leverage feature, subsuming the branch picker and becoming the primary navigation surface
4. "Review PR" should start an autonomous Claude session with a review prompt preloaded
5. pr-state.ts needs role awareness (author vs reviewer) to derive different actions for the same PR state

## Recommended Approach

**Approach B: Intent-Based Picker + Role Actions.**

It delivers the core value (intent-based picker, role-aware actions, session context handoff) without the operational complexity of background automation. The SessionIntent abstraction sets up Approach C as a natural future extension.

## Architecture: SessionIntent

The key new abstraction. A `SessionIntent` represents what the user wants to do, resolved from the item's state and the user's role.

```typescript
type SessionIntentType =
  | 'review-pr'        // Start/resume a PR review session
  | 'fix-conflicts'    // Open worktree and resolve merge conflicts
  | 'fix-errors'       // Fix failing CI checks
  | 'resolve-comments' // Address review comments
  | 'merge-pr'         // Link to GitHub merge (not a session)
  | 'create-pr'        // Start session to create PR
  | 'open-branch'      // Create worktree + session for branch
  | 'start-from-issue' // Create branch + worktree + session from issue
  | 'resume-session'   // Jump to existing session
  | 'archive'          // Clean up merged/closed PR worktree

interface SessionIntent {
  type: SessionIntentType;
  label: string;           // Button text: "review", "fix conflicts", etc.
  color: StatusColor;      // From DESIGN.md semantic colors
  prompt: string | null;   // Claude prompt to inject, or null for non-session actions
  existingSessionId?: string; // If resuming
  existingWorktreePath?: string; // If jumping to worktree
}

// Discriminated union for picker items
type PickerItem =
  | { kind: 'pr'; pr: PullRequest }
  | { kind: 'branch'; name: string; ahead: number; behind: number; prNumber: number | null; repoPath: string }
  | { kind: 'issue'; issue: GitHubIssue };
```

**Resolution flow:**
1. `resolveIntent(item: PickerItem, role: 'author' | 'reviewer', sessions: Session[], worktrees: Worktree[])` -> `SessionIntent[]`
2. Always returns at least one intent. First is primary (shown as button), rest are secondary (shown on expand/hover)
3. Same resolver used by picker, dashboard rows, and top bar
4. `resolveIntent` calls `derivePrAction` internally for PR items (derivePrAction is extended with role, not replaced). For branch and issue items, resolveIntent handles the logic directly.

## Architecture: Role-Aware State Machine

Extend `PrStateInput` with `role`:

```typescript
interface PrStateInput {
  // existing fields...
  role: 'author' | 'reviewer';  // NEW
}
```

Role changes the action derivation:
| PR State | Author Action | Reviewer Action |
|----------|--------------|-----------------|
| Open, mergeable, all clear | Merge (green) | Review (blue) |
| Open, conflicts | Fix Conflicts (red) | Fix Conflicts (red) |
| Open, CI failing | Fix Errors (red) | (muted, waiting) |
| Open, CI pending | Checks Running (yellow) | Checks Running (yellow) |
| Open, unresolved comments | Resolve Comments (accent) primary + Review (muted) secondary | Review (blue) primary + Resolve Comments (accent) secondary |
| Draft | Ready for Review (muted) | (hidden) |
| Merged/Closed | Archive (muted) | Archive (muted) |

## Architecture: Picker Tabs

### All Tab
- Mixed results across PRs, branches, issues
- Grouped by category with section headers: "pull requests", "branches", "issues"
- Items ranked by urgency: review-requested PRs first, then conflicts, then everything else

### PRs Tab
- Grouped by role: "needs your review" first, then "your pull requests"
- Each row shows: status dot, title, metadata (number, author, age), badges (review requested, has session, has worktree), intent buttons
- "Checks running" PRs show disabled "waiting..." button

### Branches Tab
- Fuzzy search filters in real-time
- Shows ahead/behind count, associated PR number if one exists
- Branches with existing sessions show "resume" as primary intent
- Branches without sessions show "open" (creates worktree + session)
- Dot color: `--status-success` (green) if has PR, `--text-muted` (#888) if no PR

### Issues Tab
- Grouped: "assigned to you" first, then "recent issues"
- Label badges use semantic colors (bug=red `--status-error`, enhancement=blue `--status-info`, feature=accent `--accent`)
- "start" intent = create branch from issue title + worktree + session with issue context in prompt
- Footer explains the pipeline: enter creates the full chain
- **Issue context prompt template:** `"Work on issue #{number}: {title}\n\n{body}\n\nLabels: {labels.join(', ')}"` — includes issue number, title, full body text, and label names. Does NOT include comments (too noisy for initial context, can be fetched by Claude if needed).
- **Branch naming:** `{type}/issue-{number}-{slug}` where type is derived from labels (bug -> fix, enhancement -> feat, default -> feat) and slug is the first 5 words of the title, lowercased and hyphenated. Example: `fix/issue-45-mobile-virtual-keyboard-covers`

### Empty and Error States
- **All tabs, API error:** Show `"could not load {tab name}. retry?"` with a ghost-style retry button
- **All tabs, zero results from search:** Show `"no results for '{query}'"` with muted text
- **PRs tab, no PRs:** Show `"no open pull requests"` — no CTA, since PR creation happens from the session
- **Branches tab, no branches:** Show `"no branches found"` (this should not normally happen)
- **Issues tab, no issues:** Show `"no open issues"` with a link to create one on GitHub

### Mobile Adaptation
- Picker goes full-screen (no overlay gap)
- Actions wrap below content (stacked layout)
- Badges abbreviated (review, worktree, session)
- Touch targets >= 44px row height
- "close" replaces "esc" in search bar

## Architecture: Picker Component Structure

```
OpenPicker.svelte (modal container, extends Spotlight)
  |-- PickerSearch.svelte (search input with / icon)
  |-- PickerTabs.svelte (all/prs/branches/issues tab bar)
  |-- PickerResults.svelte (virtualized result list)
  |     |-- PickerResultRow.svelte (single result with intent buttons)
  |     |-- PickerCategoryHeader.svelte (section divider)
  |-- PickerFooter.svelte (keyboard hints, result count)
```

**Composition:** OpenPicker renders Spotlight as its modal shell (Spotlight handles the overlay, focus trap, esc-to-close). OpenPicker owns the tab state, search state, and result rendering.

Data fetching: TanStack Query with separate query keys per tab. "All" tab merges results from PR, branch, and issue queries. Branch data from existing `/api/branches` endpoint. PR data from existing `/api/dashboard` endpoint. Issue data from existing `/api/github/issues` endpoint.

**List rendering:** Simple scrollable list, not virtualized. Picker results are typically <50 items (open PRs + recent branches + assigned issues). Virtualization is premature optimization here. If performance becomes an issue, add tanstack-virtual later.

## Bug Fix: Dashboard Review CTA

Two changes to RepoDashboard.svelte:

1. Pass real `unresolvedCommentCount` and `role` to `prActionForRow()` instead of hardcoding zeros
2. Wrap the existing `derivePrAction()` call with `resolveIntent()`, which calls `derivePrAction` internally with the role field, so dashboard rows get the same role-aware actions as the picker. `derivePrAction` continues to exist as the PR-specific state machine; `resolveIntent` is the higher-level resolver that handles all item types.

## Resolved Design Decisions

- **Session reuse semantics:** "Resume" navigates to the session within the current browser tab (same as clicking a session in the sidebar). If the session exists but is on a different connected backend, show the session as "active on {device}" with a muted badge and offer "create new" instead. No cross-device session takeover in this iteration.
- **Issue-to-branch naming:** `{type}/issue-{number}-{slug}` — resolved in Issues Tab section above.
- **Keyboard shortcuts:** Picker opens with `/` key (matches the `/` icon in the search bar). Cmd+K also works as an alias. Tab key cycles through tab bar items. Arrow keys navigate results within the active tab.
- **`derivePrAction` vs `resolveIntent`:** `resolveIntent` wraps `derivePrAction` for PR items. `derivePrAction` is extended with `role`, not replaced. For branch and issue items, `resolveIntent` handles the logic directly.
